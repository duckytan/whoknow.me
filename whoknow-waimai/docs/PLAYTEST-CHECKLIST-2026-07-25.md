## 0. 验收口径

| 判定 | 条件 |
|---|---|
| **PASS** | 自动化全绿 + 笑率达标 + 同店第 5 单差异目测成立 + 无障碍无阻断项 |

## 1. 硬项（不可妥协）

### H1 笑率（核心 KPI）
- **方法**：招募 ≥ 8 名未经剧本洗脑的真人 tester，每人连续玩 **≥ 12 单**（覆盖普通/穷鬼/备注/奇葩地址/同店递进），每单对「四阶段段子时间线」打 **1–5 分**（5=笑出声，1=无感甚至不适）。
- **口径**：
  - 中位分 **≥ 3.5** 且 **≥ 60% 的订单 ≥ 4 分** → 过
  - 中位 **3.0–3.4** → CONCERNS（上线 + 列 P3）
  - 中位 **< 3.0** → FAIL
- **记录**：`docs/playtest/<日期>-results.csv`（tester, 单号, 分支id, 评分, 备注）

#### 代码级代理（CI 可跑，先于真人，防止回归）
- **脚本**：`scripts/playtest-sim.ts`（蒙特卡洛 1500 会话 ×12 单，种子可复现），报告见 `docs/PLAYTEST-SIM-2026-07-25.md`。
- **指标与当前实测**（P3 变体池扩至 40 分支后）：
  - 每会话「不同台词链数」均值 **10.2 / 12** → 门槛 **≥ 9** ✅
  - 单分支重复 ≥3 次的会话占比 **28.0%** → 门槛 **< 30%** ✅（真人 H1 笑率为最终判据）
  - 基线变体池 8 条（default~h）全部出现；40/40 分支可达（无死分支，`dramaEngine.coverage.test.ts` 守）
- **说明**：12 单里要撞车率 < 30% 在数学上需 ~185 条不同链（生日悖论），不现实；故以「不同链均值 + 单分支过饱和占比」作代码级代理，真笑率仍靠真人 H1。

### H2 同店第 5 单差异（已上线功能，需真机确认生效）
- **步骤**：固定一家店（如 s01），连点 **5 单**（第 1/3/5 单重点观察）。
- **断言**：
  - 第 3 单命中 `regular_3rd`（文本含「第 3 次」类表述）+ 解锁成就 `regular`
  - 第 5 单命中 `vip_5th`（文本含「第 5 单 / VIP」）+ 解锁成就 `vip_fan`
  - 第 5 单台词与第 1 单**明显不同**（差异感成立，非单纯换数字）
- **自动化等价**：`dramaEngine.test.ts` T14 已验证 `shopVisitCount>=3` 命中；第 5 单逻辑同源，真机为兜底确认。

### H3 成就全可达（12/12）
- **断言**：12 个成就（`poor_meal / cheap_ghost / bankrupt_legend / overeat_warn / dark_chef / fate_bound / reconciled / spicy_soul / peace_please / lost_rider / regular / vip_fan`）在完整 playtest 轨迹中均可解锁。
- **自动化等价**：`SEED-REVIEW-2026-07-25.md` 已静态证明 12/12 可达；真机为实测确认。

### H4 无障碍无阻断
- 文字对比度 ≥ 4.5:1（品牌绿/橙/紫仅用于强调，不担正文）
- 正文 ≥ 14px，段子卡手写体仅作装饰、关键信息有常规体备份
- 点击热区 ≥ 44×44px；无「仅靠颜色」传达的状态
- 无自动播放音/强闪烁（避免光敏风险）

## 2. 软项（可先上线后调）

### S1 重复疲劳（P2 第一刀 + P3 扩池，已验证收益）
- **步骤**：同一 tester 连玩 **20 单普通单**，记录命中的分支 id 序列。
- **断言**（代码级，见 H1 代理）：
  - 基线变体池 **8 条**（default~h，均 isFallback `1=1`）在长会话中**均会出现**
  - 5 家店 / 3 骑手专属各 **2 变体**，店/骑手人格分支成为主要多样性来源
  - 每会话不同台词链均值 ≥ 9；单分支重复 ≥3 次会话占比 < 30%
- **已实现机制**：共 40 分支（基线 8 + 店 10 + 骑手 6 + 穷鬼 2 + 黑暗料理 3 + 其余专属）；权重池随机。`dramaEngine.coverage.test.ts`（2000 会话）守死分支；`playtest-sim.ts` 出代理指标。
- **待观察**：真机上是否仍感重复（权重/变体可再调，见 §4）。

### S2 概率平衡
- 稀有/传说分支（破产/宿世姻缘/黑暗料理/拉黑重逢）实际触发率是否「惊艳不泛滥」；若某分支占比异常高/低，回 `DRAMA-SEED` 调 `weight`/`probability`。

### S3 文案风味
- 是否存在「梗过期/地域冷/梗太密」的台词；收集 tester 自由吐槽，进 P3 文案库。

## 4. 调优抓手（若 H1/S 不达标，去哪改）

| 症状 | 改哪 | 怎么改 |
|---|---|---|
| 普通单重复感强 | `DRAMA-SEED` 基线变体 | 加更多 `default_x`（isFallback, `1=1`），或调权重让原 `default` 占比更低 |
| 穷鬼/黑暗料理撞句 | `poor_b` / `odd_eats_b/c` | 同条件再加变体分支 |
| 稀有分支太少/太多 | `weight` / `probability` | 调权重池分布 |
| 某台词不好笑 | 对应分支 `chain[].text` | 改文案，纯 JSON，无需动引擎 |
| 无障碍 | `src/style.css` + 组件 | 对比度/字号/热区 |

> 所有调优均为 **JSON / CSS 层**，引擎与类型不动；改完跑 §3 自动化即知是否回归。
