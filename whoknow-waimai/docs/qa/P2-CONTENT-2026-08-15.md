## 2. 改造 ①：骑手线变体池（破 R4，最关键）

**新增常量**（源码 `sliceDrama.ts` 第 237–244 行）：

```typescript
// 骑手备注回声（P2 第一刀破 R4）：骑手对用户备注的口语化反应（快递小哥人格），
// 确定性、零随机。拼接于 RIDER_LINE 基础句之后；空串 '' 表示骑手不接该备注。
//   6 条均给非空回声，以彻底破除「骑手线 24 组合仅 5 句不同、每句重复 4–6 次」的重复疲劳。
const RIDER_REMARK_MODIFIER: Record<RemarkTag, string> = {
  more_spicy: '（辣味隔着打包袋直窜我鼻子，你自求多福）',
  less_spicy: '（清汤寡水的，老板说你养生我信了）',
  no_cilantro: '（香菜？我闻着都嫌弃，一根没给你放）',
  no_scold: '（你倒替老板说话，我都不敢催了）',
  perform: '（还演出呢？下回给我也整一段）',
  boss_thx: '（老板被你夸得乐呵，我顺带沾光了）',
}
```

**拼接改造**（源码第 308–310 行）：

| | 改前 | 改后 |
|---|---|---|
| `deliverText` | `RIDER_LINE[cookSlow?'slow':'fast'][input.addressTag]` | `RIDER_LINE[cookSlow?'slow':'fast'][input.addressTag] + (RIDER_REMARK_MODIFIER[input.remarkTag] ?? '')` |

- **改前**：骑手 `deliver` 仅承接地址情境（slow/fast 两版 + 4 地址 = 5 句不同），24 组合里每句重复 4–6 次 → 复玩即穿帮（"骑手零变体"弱点）。
- **改后**：6 条备注回声**全非空**，每个 `(addr, remark)` 的 `deliver` 唯一可辨；骑手对玩家选择有即时反应，强化「真实外壳 × 胡闹内核」反差。
- **Why more screenshotable**：原来骑手台词跨单雷同、无记忆点；现在"你点多放辣，骑手吐槽辣味窜鼻子""你夸老板，骑手顺带沾光"——带人格、可截图、可玩梗。

> **R4 处理**：原 R4 规定"deliver 不接备注"。本刀**主动打破**该子句（已记入一致性契约）。R4 其余子句（accept 引入、cook/complete 各呼应一次）仍有效。确定性不变（`RIDER_REMARK_MODIFIER` 纯查表、零随机，S2「无随机」仍成立）。

## 3. 改造 ②：家庭双情绪带拆分

**改动位置**（源码 `home` 块，第 140–151 行）：

| | 改前（单人格） | 改后（双人格） |
|---|---|---|
| `home.neutral.cook` | `（哼着歌）家的味道，火候我拿捏得准` | `（家常味儿，火候我随手掂的）` |
| `home.warm.cook` | `（哼着歌）家的味道，火候我拿捏得准` | `（哼着歌）家里的味道，闭眼都拿捏得准。`（**保持不变**） |
| `home.neutral.accept` | `家庭单？跟给自己家做一样，随便坐。`（保持） | 同左（保持） |
| `home.warm.accept` | `家庭单？跟回自己家一样，门都不用敲。`（保持） | 同左（保持） |

- **改前**：`home` 的 neutral(55) 与 warm(60+) 在 accept/complete 有区分，但 **cook 线共用同一句**，双档老板"做饭态度"无差异，中性家庭单与温馨家庭单观感接近。
- **改后**：neutral 用"家常味儿，火候我随手掂的"（敷衍家常、随性），warm 用"家里的味道，闭眼都拿捏得准"（真当家人、上心）。两档老板"做饭人格"可感知地拉开。
- **Why more screenshotable**：55 分（少辣/去香菜）对比 60+ 分（多辣/别骂了/表演/夸老板）的家庭老板，从"随便做做"到"门都不用敲、闭眼拿捏"，档位对照的温情反差更明显，适合截图对比玩梗。
- **数值模型零改动**：偏移量表（`ADDRESS_OFFSETS`/`REMARK_OFFSETS`）原样保留；`more_spicy` +5 → `home+more_spicy=60` 落 warm 带，符合既有数值模型，无需调阈值。

## 4. 改造 ③：ICU / 家庭 收尾 punch-up

经核查，既有收尾句已满足"温柔 / 可分享 / 守红线"要求，**予以保留（无文字改动）**，作为可截图收尾：

| 位置 | 收尾句（已保留） | 评价 |
|---|---|---|
| `icu.warm.complete` | `趁热趁软乎……您慢用，好好休息。（这单我比查房还上心）` | 温柔中性、带「比查房还上心」可截图梗；**守红线**（"ICU 病房"中性表述、无死亡/暴力/竞品） |
| `home.neutral.complete` | `拿好，趁热吃——再不吃咱妈要打电话查岗了。` | 生活化、带妈查岗梗，易分享 |
| `home.warm.complete` | `拿好，趁热吃，家里人惦记你呢。（碗我顺手洗了）` | 温情上心、碗顺手洗了，强化"真当家人"反差 |

- **Why（设计判断）**：任务要求"ICU 收尾温柔+可截图、家庭收尾更可分享"。既有文本已达标，强行改写反而有触碰红线的风险（如过度玩笑化医疗场景）。故采用"保留即达成"策略，将改造精力集中在确定性更安全、收益更高的 ①② 两项。
- 若主理人希望 ICU 收尾再加强（如 `icu+more_spicy` 单独温柔化"辣子我少放了，您尝个味儿"），属新增按地址细分的备注变体，需单独立项，不在本刀范围。
