> **设计**：design-strategist（文策渊 / Vince Coyer）
> **任务 ID**：T-RS-01
> **性质声明**：纯设计文档，**不写代码、不改 `src`、不改 `sliceDrama`/`dramaEngine`、不执行 git**。所有落地动作以「衔接点 + 实现注意点」清单列出，供 engineering-lead 直接照做、不返工。

## 0. 总纲对齐声明（必须第一条读）

### 0.1 产品总纲铁律（已记入项目记忆，本规格对齐）

> **真实外壳 × 胡闹内核 = 反差喜剧**
> 界面 / 流程 / 地图 / 时间线 必须极度真实（像真美团）；唯一不真实的是两样——① 对话内容（胡闹荒诞）② 这单外卖本身是假的（虚拟 / 锡哥手编）。
> 外壳越真，内核越胡闹越好笑。真实是喜剧的放大器。

### 0.2 本规格的边界（只动"壳"，不动"核"）

本规格只重做**三块外壳的拟真度**：地图、对话气泡、推送通知。明确不触碰：

| 不动的东西 | 原因 |
|---|---|
| `DramaEventOut` 数据结构（`phase/actor/text/moodDelta?/delay?`） | 规格必须贴合引擎，已验证 OK |
| `sliceDrama.ts` 的 4 事件确定性产出 | 真机走查通过，因果链不动 |
| 4 条台词的**文本内容**（老板/骑手/系统） | 那是胡闹内核，越胡闹越好，本规格只改其"外壳呈现" |
| 任何 `<input>` / 自由文本框 | 宇宙级原则：零自由文本 |
| 红线门控（forbiddenCheck） | 合规层不动 |

### 0.3 本规格要达成的三句话

1. **地图**：从"风格化装饰图形"升级为"真实配送路网 + 骑手沿线行进 + ETA 跳秒倒计时"。
2. **对话**：把 `DramaTimeline` 的"逐条演出时间线"重包为"真实 IM / 商家聊天 UI"，台词不变、只换皮。
3. **推送**：新增"纯外壳系统通知"，每个阶段切换弹一条真实推送（零胡闹），用真实感反衬内核荒诞。

### 0.4 视觉锚点（唯一事实来源 = `src/style.css` 设计令牌）

本规格所有配色**只引用以下令牌**，不新造色值（避免与现有美团皮脱节）：

## 1. 地图（重做 · 当前最弱）

### 1.1 现状与问题（实读 `OrderView.vue` + `style.css`）

现有 `.map`（`OrderView.vue` 结果态）结构：

```
.map (height:200px, 渐变蓝灰背景)
 ├─ .road      // 40px 网格线，纯装饰
 ├─ .from      // 左下黄点（商家）
 ├─ .to        // 右上红点（目的地）
 ├─ .route     // 一条水平直线渐变（黄→红）
 ├─ .rider-dot // 静态 🛵，固定在 left:56% top:50%
 └─ .topbar    // 返回 / "订单详情" / 📞
```

**问题**：
- 骑手点**全程静止**，不沿路线移动，与"配送中"语义完全脱节。
- `.road` 是 40px 方格网，像方格纸，**不像高德/美团路网**。
- 无 ETA、无阶段联动、无真实路名/地块质感。
- 路线是一条直线，不"贴路"。

### 1.2 设计目标 / 真实要素清单（地图必须 100% 真实）

| # | 真实要素 | 说明 |
|---|---|---|
| M1 | 真实路网质感 | 街道（白线）+ 地块（浅灰块）+ 可选公园/水域，像高德/美团底图 |
| M2 | 骑手沿线行进 | 🛵 沿 polyline 从商家→目的地，动画时长 ≈ 订单总时长 |
| M3 | ETA 跳秒倒计时 | 与骑手点位置联动，真实量级（分钟），逐秒跳动 |
| M4 | 阶段联动 | 出餐阶段骑手在商家；配送阶段动点沿线走；完成阶段到点 |
| M5 | 真实标记 | 商家 pin（黄）/ 目的地 pin（红，带地址 emoji），带白色描边 + 软化光晕 |
| M6 | 真实状态条 | 地图内显示"阶段 + ETA"状态条，像美团配送追踪页 |

**内核边界**：地图**不承载任何胡闹台词/段子**；胡闹只在聊天气泡（§2）与"锡哥手编"水印（§4.5）里。地图是纯真实放大器。

### 1.3 视觉规格

**背景与路网（真实质感）**：

| 图层 | 规格 | 颜色 |
|---|---|---|
| 底图 | `<rect>` 铺满，`fill:url(#mapBg)` | 线性渐变 `#E8EDF2`→`#DCE4EC`（冷灰，高德风） |
| 地块 | 6~8 个圆角 `<rect>`，`rx=6`，轻微描边 | `fill:#F4F7FA` `stroke:#E2E8EF` |

| 图层 | 规格 | 颜色 |

**标记（pins）**：

| 标记 | 坐标(viewBox) | 样式 |
|---|---|---|
| 商家 | `(60,150)` | 圆 `r:10` `fill:--mt-yellow` `stroke:#FFF sw:3`；中心 emoji `🍳`/`🏪`；外 halo 圆 `r:16` `fill:rgba(255,209,0,.25)` |
| 目的地 | `(345,55)` | 圆 `r:10` `fill:--mt-price` `stroke:#FFF sw:3`；中心 emoji = 地址 emoji（`🚽`/`🏥`/`🏠`/`🏢`）；halo `r:16` `fill:rgba(255,75,16,.22)` |
| 骑手 | 动态（见 §1.4） | `<g transform="translate(x,y)">` 圆 `r:14` `fill:--role-rider` `stroke:#FFF sw:3`；emoji `🛵` 16px 白字居中；可选运动拖尾 |

**ETA / 阶段状态条（地图内真实元素）**：保留现有 `.topbar`（返回 / "订单详情" / 📞），在其下方加一条真实状态条：

```
[🛵 预计 28:00 到达]   [商家备餐中 ▦]
```

- 左：ETA 胶囊（`background:rgba(0,0,0,.45)` 或白底 pill，`color:#FFF/#222`），显示 `mm:ss`，**逐秒跳动**（见 §1.4）。
- 右：阶段标签（"等待接单" / "商家备餐中" / "骑手配送中" / "已送达"），随阶段切换。

### 1.4 动效与阶段联动（核心）

**统一时钟建议**：地图、聊天（§2）、推送（§3）应共享**同一个"逐条 reveal 时钟"**（见 §5.1 `useDramaProgress`）。地图只消费其暴露的 `currentPhase` 与 `phaseProgress`。

**三态联动**（对应 4 个 phase 的进入点）：

| 阶段（phase 进入） | 地图状态 | 骑手点位置 `p` | ETA | 阶段标签 |
|---|---|---|---|---|
| `accept` 接单 | 在商家 | `p = 0`（停在商家 pin） | 满（`etaTotal`） | 等待接单 |
| `cook` 出餐 | 在商家 | `p = 0` | 满 | 商家备餐中 |
| `deliver` 配送 | **沿线行进** | `p: 0 → 1`（eased） | 满 → `00:00`（跳秒） | 骑手配送中 |
| `complete` 送达 | 到目的地 | `p = 1`（停在目的地 pin） | `00:00` | 已送达 |

**骑手点插值（工程做法）**：用 SVG `path.getTotalLength()` 取路线总长 `L`，每帧 `pt = path.getPointAtLength(p * L)`，把 `<g>` 的 `transform` 设为 `translate(pt.x, pt.y)`。无需 SMIL，受 Vue 响应式 `p` 驱动，天然与聊天/推送同步。

**ETA 公式（与 `p` 联动，纯函数）**：

```
etaTotal   = etaForAddress(addressTag)        // 视图层纯函数，见 §5.2，确定性
etaRemain  = ceil(etaTotal * (1 - p))          // p∈[0,1]，整数秒 → 自然"跳秒"
显示        = mm:ss(etaRemain)                  // 如 28:00 → 27:59 → … → 00:00
```

- `etaForAddress` 量级参照真实配送（分钟级），例如：`home=28min`、`company=22min`、`icu=35min`、`toilet=40min`（确定性映射，可加备注微调 ±1~3min）。**量级真实**，但倒计时随 `p` 压缩到"配送阶段在屏时长"内走完 → 既真实又和骑手点同步。
- "跳秒"实现：因 `etaRemain` 是 `p` 的**整数天花板**，骑手移动时秒值逐整数递减，视觉即"逐秒跳动"，**无需独立计时器**。

**动效曲线**：`deliver` 阶段 `p` 由 `0→1` 用 `cubic-bezier(0.4, 0, 0.2, 1)`（ease-in-out，模拟起步→加速→临近减速）。若 `totalDelay` 大（出餐慢 + 骑手晚到），`deliver` 在屏时长按比例拉长 → ETA 跳得更慢 → 与"配送更久"语义一致。

**reduced-motion 回退**：`prefers-reduced-motion: reduce` 时，骑手点**直接跳到当前阶段终位**（不沿路径补间），ETA 仍按终值静态显示；状态条正常。已有全局规则（`style.css` 末段）兜底，地图须显式 `transition/animation: none` 回退。

## 2. 对话气泡（把 `DramaTimeline` 改成真实 IM / 聊天 UI）

### 2.1 现状（实读 `DramaTimeline.vue`）

- 左对齐时间线：头像（🍳/🛵/⚙️）+ 说话人 + 台词 + `moodDelta`/`delay` 标签 + "🎭 演出中…"。
- 逐条 reveal：`revealed` 计数 + `performingIndex`；相邻间隔随机 1.5–4s；出餐慢（`delay≥45s`）拉长到 2.5–4s。
- `pending`：`· · ·` 占位。
- 入场：`revealIn`（淡入 + 上移 14px）。
- 台词**内容**保留不动（胡闹内核）。

### 2.2 设计目标 / 真实要素清单（聊天外壳必须 100% 真实）

| # | 真实要素 | 说明 |
|---|---|---|
| C1 | 左右分列 | 老板/骑手/系统 在**左**（"对方"）；玩家选择 在**右**（"你发出的"） |
| C2 | 头像 + 昵称 | 每条带说话人头像与名字（老板/骑手/系统），像商家 IM |
| C3 | 时间戳 | 每条带 `HH:MM`（reveal 时刻的墙钟），首条可标"刚刚" |
| C4 | "正在输入…"指示 | 对端出现气泡前的三点打字指示，命名 NPC（"老板正在输入…"） |
| C5 | 实时收到节奏 | 新消息从底部推入、淡入上移，自动滚到底（保留逐条 reveal 手感） |
| C6 | 系统提示气泡 | `moodDelta`/`delay` 以"系统小通知"形式居中呈现（见 §2.5） |
| C7 | 玩家选择气泡（右·显示性） | 已选地址/备注 chip 作为一条右对齐气泡展示，**非输入、无 `<input>`** |

### 2.3 布局与气泡规格

**容器**：白底（`--mt-card`）聊天区，纵向滚动；新消息出现在底部，容器 `scrollIntoView` 自动贴底。

**气泡分列**：

| 说话人 | 对齐 | 头像位 | 气泡底色 | 文本色 |
|---|---|---|---|---|
| boss（老板） | 左 | 左，圆形 `r` 底 `--mt-yellow`，emoji `🍳` | `#FFF` + 细阴影 + 小尾标 | `--mt-text` |
| rider（骑手） | 左 | 左，圆形底 `--role-rider`，emoji `🛵` | `#FFF` + 细阴影 | `--mt-text` |
| system（系统） | 居中 pill | 无头像 | `rgba(0,0,0,.06)` 半透明灰 | `--mt-text-2` |
| 玩家（你） | 右 | 右，圆形底 `--brand-green`，emoji `🙂` | `--mt-yellow` 实底（品牌发送色） | `#1a1a1a` |

> 右气泡用 `--mt-yellow`（与"确认下单"品牌一致），读作"你发出的消息"。**绝不**使用 `<input>`/文本框——右气泡是已选 chip 的**渲染展示**。

**时间戳**：每条气泡上方或头像旁小字 `HH:MM`（`--mt-text-3`，11px）。系统 pill 不显示时间戳。

**入场动效**：沿用现有 `revealIn`（淡入 + `translateY(14px)→0`，0.5s ease）；新消息入屏后 `scrollIntoView({behavior:'smooth'})`。`prefers-reduced-motion` 下去掉位移、直接显隐。

### 2.4 玩家选择气泡（右·显示性·非输入）

**出现时机**：进入结果态时**立即**作为聊天第一条（最上方）渲染，时间戳 = 下单时刻。

**内容**：把已选的 `addressTag` + `remarkTag` 以 chip 形式展示在右气泡内，例如：

```
[🙂 你]                                  14:03
        ┌─────────────────────────┐
        │ 🚽 公厕   🤐 别骂了      │   ← 两个 chip 展示，纯渲染
        └─────────────────────────┘
```

- 数据来源：现有 `OrderView` 的 `addressChips` / `remarkChips` 已含 `label`/`emoji`，直接复用，零新增。
- **无 `<input>`、无可编辑态**：这就是"显示性玩家发言"的落地。与 §0 宇宙级原则一致。

### 2.5 `moodDelta` / `delay` 如何自然融入气泡（C6）

胡闹内核的 meta 数值（老板心情变化、配送延时）以**聊天系统小通知**形式呈现，读起来像真 App 的"对方拍了拍你 / 骑手预计晚到"——真实外壳、微透 meta：

| 来源字段 | 呈现形式 | 示例文案 | 样式 |
|---|---|---|---|
| `ev.moodDelta`（boss，且 `≠undefined && ≠0`） | boss 气泡下方的居中系统 pill | `老板心情 ＋5 😊` / `老板心情 −30 😠` | 绿(`--brand-green`)/红(`--mt-price`) 文字，半透明灰底 |
| `ev.delay`（cook 阶段，`>0`） | 居中系统 pill | `⏱ 出餐较慢 ＋45s` | `--role-rider` 文字 |
| `ev.delay`（deliver 阶段，`>0`） | 居中系统 pill | `⏱ 骑手预计晚到 ＋25s` | `--role-rider` 文字 |

- 仅当字段存在且非零/非零延时才显示，避免 `+0`/`⏱0s` 噪声（与现有切片逻辑一致）。
- 这些 pill **不破坏真实感**：真实外卖 App 确有"出餐慢/骑手晚到"系统提示，反而强化真实。

### 2.6 "正在输入…"指示（替代"🎭 演出中…"）

- 当 `performingIndex === i`（NPC 正准备发这条），在**该 NPC 左侧**先显示打字气泡：三点跳动 `+ "老板正在输入…"` / `"骑手正在输入…"`（命名 NPC，传达"这个 NPC 正在为你演这条"）。
- 打字气泡停留 ≈ 现有"演出中"时长（出餐慢阶段相应拉长），随后替换为真实台词气泡（淡入推入）。
- **🎭 演出中 内联指示退役**：其喜剧意图一分为二——"实时感"由打字指示承担（真实），"这是演的"由 §4.5 水印承担（meta）。二者合起来既真实又点破第四面墙，不互相打架。

### 2.7 与现有结构映射（`DramaTimeline.vue` → 聊天 UI）

## 3. 推送通知（新增 · 纯外壳 · 零胡闹）

### 3.1 目标 / 真实要素清单

| # | 真实要素 | 说明 |
|---|---|---|
| P1 | 真实系统推送样式 | iOS 锁屏 banner / 美团 in-app toast 二选一或叠加 |
| P2 | 阶段触发 | 4 个 phase 进入点各弹 1 条 |
| P3 | 零胡闹 | 文案 100% 真实配送用语，绝无段子 |
| P4 | 非模态 | 顶部滑入、自动消失、不挡操作 |
| P5 | 与地图/聊天联动 | 同源于 `useDramaProgress`，与骑手移动、气泡 reveal 同步 |

> 设计意图：推送是**最纯的真实外壳**，它越像真系统通知，就越反衬出聊天里 NPC 的胡闹——"真实是喜剧的放大器"的极致用法。

### 3.2 四条通知映射（phase → 文案 / 触发点）

| phase 进入 | 通知标题 | 通知正文（真实用语） | 触发点 |
|---|---|---|---|
| `accept` | 商家已接单 | "XX 商家已确认您的订单" | accept 事件 reveal 时 |
| `cook` | 商家备餐中 | "商家正在备餐，请稍候" | cook 事件 reveal 时 |
| `deliver` | 骑手已取餐·配送中 | "骑手已取餐，正在赶来（预计 mm:ss）" | deliver 事件 reveal 时（骑手开始沿线走） |
| `complete` | 订单已送达 | "订单已送达，请取餐 🎉" | complete 事件 reveal 时（骑手到点） |

> 文案对齐任务示例（"商家已接单 / 骑手已取餐出发 / 配送中 / 订单已送达"），此处按 4 phase 细化成 4 条不重样、且更贴近美团真实推送。

### 3.3 样式规格

**A. iOS 锁屏 banner（推荐主样式）**：

```
┌──────────────────────────────────────────┐
│  🛵 美团外卖            现在 / 14:05      │  ← 毛玻璃深卡，app icon + 应用名 + 时间
│  骑手已取餐·配送中                        │
│  "骑手已取餐，正在赶来（预计 26:12）"      │
└──────────────────────────────────────────┘
```

- 容器：宽 100%（max `414px`），`top:0`，`padding:10px 14px`，`background:rgba(30,30,32,.9)` + `backdrop-filter:blur(20px)`，`border-radius:0 0 14px 14px`，`box-shadow:var(--shadow-pop)`。
- 图标：圆角方 `28×28`，`background:--mt-yellow`，emoji `🛵`/`🍳`。
- 应用名：`--mt-text-2`/白，`font-weight:700`；时间：`--mt-text-3`，右对齐。
- 标题：白，`14px`，`font-weight:800`；正文：白 `13px`，`opacity:.9`。

**B. 美团 in-app toast（备选/叠加）**：浅色细条，`background:#FFF`，左侧小黄点 + 黑字，从顶部下滑，更像 App 内"消息提醒"。用于不想"跳戏到锁屏"的场景。

> 推荐：**以 A（iOS 锁屏 banner）为主**，因其"真实推送"感最强、反差最大；B 作为设置项备选。

### 3.4 触发时机 / 停留 / 联动

- **触发**：由 `useDramaProgress` 在 phase 切换瞬间 `emit` 一条通知事件；`PushNotifier` 监听并展示。
- **入场**：`transform: translateY(-120%) → 0`，`cubic-bezier(0.2,0.8,0.2,1)`，~320ms。
- **停留**：`3500ms` 后自动 `translateY(-120%)` 滑出（或上滑消失）。
- **非模态**：不拦截点击；期间用户可照常看地图/聊天。
- **联动**：`deliver` 通知出现 ⇔ 地图进入 `enRoute`（骑手沿线走）+ ETA 开始跳秒 ⇔ 聊天骑手气泡 reveal。三者同相位。
- **去重/防抖**：同一 phase 只弹一次；`reduced-motion` 下去掉滑入、改为淡入、停留不变。

### 3.5 推送局部边界

- ✅ 真实：样式、文案、触发、停留、非模态。
- ❌ 胡闹：**零胡闹**，推送里绝不出现段子/锡哥/荒诞词（那是聊天与水印的事）。

### 4.5 水印（"锡哥手编"）放置裁定 —— 对齐 GDD §9.5

[🎭 锡哥精选段子]                        （小黄徽标，保留原 badge）

- 读起来像真实免责声明（真实外壳），**内容却是破墙笑点**（这单是假的/手编的 = 内核明示）。真实与胡闹在同一行里完成反差，且不污染截图爆点。

- 不改其文案语义，只移位 + 轻样式。

## 5. 给 engineering-lead 的实现注意点（落地清单 · 设计视角）

> 以下为"怎么落地不返工"的设计约束；具体代码由 engineering-lead 实现（本规格不写码）。

1. **§5.1 统一时钟 `useDramaProgress()`（新建 composable）**
   - 拥有 reveal 时钟：依 `events` 顺序逐条 reveal；`intervalFor` 逻辑（出餐慢拉长）从 `DramaTimeline` 迁此。
   - 暴露：`currentPhase`（accept→cook→deliver→complete）、`phaseProgress`（`p∈[0,1]`，仅 deliver 阶段 0→1 变化）、`revealedCount`、`isPerforming`。
   - `MapTrack`/`DramaChat`/`PushNotifier` 全部 `inject`/引用此 composable，禁止各自 `setTimeout`。

2. **§5.2 ETA 纯函数（视图层）**
   - `etaForAddress(tag): number`（秒，确定性）。如 `home=1680, company=1320, icu=2100, toilet=2400`（可加备注微调）。
   - 仅用于地图 ETA 显示；不写入 `dramaState`、不碰 `sliceDrama`。

3. **§5.3 地图渲染（`MapTrack.vue`）**
   - inline SVG，`viewBox="0 0 414 200"`，`preserveAspectRatio="xMidYMid slice"`。
   - 骑手点：每帧 `getPointAtLength(p * L)` → `transform: translate(x,y)`；`p` 来自 `useDramaProgress.phaseProgress`。
   - ETA：`ceil(etaTotal*(1-p))` → `mm:ss`，随 `p` 整数递减即"跳秒"，无需独立计时器。
   - 替换 `OrderView` `.map` 内 `.road/.from/.to/.route/.rider-dot` 五节点为 `<MapTrack>`；`.map` 容器 + `.topbar` 保留。
   - 配色只引用 §0.4 令牌 + §1.3 地图灰渐变，禁新色板。

4. **§5.4 聊天（`DramaChat.vue`）**
   - props 同 `DramaTimeline`（`events`）。消费统一时钟的 `revealedCount`/`isPerforming`。
   - 左：boss/rider/system；右：玩家选择气泡（chip 展示，`OrderView` 的 `addressChips`/`remarkChips` 复用）。
   - 打字指示替代"🎭 演出中…"；`moodDelta`/`delay` 改居中系统 pill（§2.5）。
   - 新消息 `scrollIntoView` 贴底；保留 `revealIn` 淡入上移。
   - **硬约束**：右气泡内**绝无 `<input>`/可编辑元素**（forbiddenCheck 已禁，保持）。

5. **§5.5 推送（`PushNotifier.vue` + `<Teleport to="body">`）**
   - 监听 `useDramaProgress` 的 phase 切换事件，4 phase → 4 条（§3.2）。
   - iOS 锁屏 banner 样式（§3.3-A）为主；`top:0` 滑入，停留 `3500ms` 自动消失，非模态。
   - Teleport 到 `body`（或 phone 容器顶部），避免被 `.order-detail` 溢出裁剪。

6. **§5.6 水印移位**
   - `OrderView` 中 `.story-watermark` 从 `DramaTimeline` 上方移到结果态最末 `.page-pad` 内（"再来一单"之后），样式 fine-print 化（§4.5）。对齐 GDD §9.5。

7. **§5.7 无障碍（reduced-motion）**
   - 地图：骑手点跳终位、ETA 静态；聊天：去位移、打字指示直接出气泡；推送：淡入无滑入。沿用 `style.css` 末段全局规则，三新组件显式 `animation/transition:none` 回退。

8. **§5.8 性能**
   - 骑手点用 `transform` 位移（不触发 reflow）；SVG 静态层（路网/pins）不参与每帧重绘，仅骑手 `<g>` + ETA 文本更新。
   - 推送用 `transform` 滑入；`will-change: transform` 适量。

9. **§5.9 红线不破**
   - 不引入 `<input>`（纯点击原则）；不改动 `DramaEventOut`/`sliceDrama`；不修改任何台词 `text`。

## 6. 设计红线自查（针对本规格）

| 红线 | 本规格是否触发 | 说明 / 缓解 |
|---|---|---|
| 主导策略（dominant strategy） | 否 | 纯呈现层，无新机制/数值，不产生最优解 |
