# 胡闹外卖 P2 上线后验证计划（替代笑率闸门）

## 背景

笑率闸门（真人体验"东西好不好笑"）已正式豁免（`docs/qa/P1-GATE-WAIVER-2026-08-15.md`）。P2 没法在上线前用真人笑率把关，因此改用**上线后的重复疲劳代理指标**回收验证：

> 东西好不好笑 ≈ 用户愿不愿意截图分享 + 愿不愿意复玩。

这把"主观好笑"翻译成两个可量化的行为信号，正好对齐产品**传播铁律**（每个交互要能截图发朋友圈）。

## 两个代理指标

| 指标 | 定义 | 反映什么 |
|---|---|---|
| **截图分享率** | `share_click` 事件数 ÷ 独立访客数 | 这个互动值不值得发朋友圈（传播力） |
| **复玩率** | `replay` 会话数 ÷ 独立访客数 | 看一遍够不够、会不会因为重复而腻（可持续性） |

## 怎么测

- **前期轻量（现在就做）**：
  - 客户端埋点 `src/analytics/tracker.ts`：捕获 `share_click` / `replay`（设计见 `docs/architecture/INSTRUMENTATION.md`）。
  - 早期种子用户（你自己 + 几个朋友）手动看：走几单，记下来哪句好笑、哪句腻。
- **后期（该花就花时）**：接后端 / 分析服务（如 Vercel Analytics 或自建轻量端点），自动汇总 `share`/`replay` 到看板，免去手动 localStorage 读取。

## 阈值建议（先观察、后定死）

> 原则：先跑 1–2 周拿基线，再定硬阈值，别一上来就卡死（守"质量>数量"）。

- **分享率健康线**：建议观察基线后设 ≥ 15–20%（虚拟外卖分享欲中等，凭早期数据校正）。
- **复玩率**：首周建议 ≥ 30% 表示愿意二刷；若复玩率随天数骤降 + 分享率低 = **重复疲劳预警**。
- 各地址×备注组合的 share/replay 分布单独看：哪组最腻、哪组最香。

## 回收节奏

- 上线后 **第 1 / 3 / 7 / 14 / 30 天** 各回看一次 stats。
- 读取方式：前期 `tracker.getStats()`（localStorage）；后期看板。

## 触发 P3 内容扩容的条件

- 任一组合 `share` 显著低于均值，或 `replay` 在 7 天内腰斩 → 该组合判定"内容疲劳"，启动新段子批次（P3 铺量，但守"先严后松"）。
- 代理指标连续 14 天健康 + 早期用户主观"好笑"反馈一致 → **正式关闭笑率闸门豁免**，P2 闭环转入常规运营。

## 关闭豁免的判据（签字线）

1. 代理指标（分享率/复玩率）稳定 14 天达健康线；
2. 早期种子用户主观反馈"好笑/愿分享"一致；
3. 主理人签字确认。

满足三条 → 豁免关闭，P2 收口完成。
