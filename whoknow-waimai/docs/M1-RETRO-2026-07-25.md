### 构建配置重构（P8 详细）

- **现象**：`vue-tsc -b`（build 模式）报 `TS6310: Referenced project 'tsconfig.node.json' may not disable emit.`
- **根因**：build 模式要求被引用的 composite 工程必须可 emit 产物（tracking artifacts），`noEmit:true` 与之冲突；即便 TS 5.9.3 支持命令行级 `--noEmit`，工程 config 内 `noEmit` 仍被拒。
- **修复**：
  1. 从 `tsconfig.json` 删除 `references` 字段（不再引用 `tsconfig.node.json`）。
  2. `package.json` 的 `build` 改为 `vue-tsc --noEmit && vite build`（单工程、非 build 模式）。
  3. 删除孤立的 `tsconfig.node.json`（vite.config.ts 由 Vite/esbuild 转译，不参与 `vue-tsc` 类型检查）。
- **结果**：`vue-tsc --noEmit` 零错误，Vite 打包 `dist/`（dist/index.html + assets/index-*.js 110KB + css），根目录无残留文件。

## 3. 关键设计决策

- **兜底优先级**：`default` 分支 `condition:"1 = 1"` + `isFallback:true`，命中逻辑为「先滤掉 fallback 取候选，候选为空才退回到 fallback」，修复「普通 ¥50 订单零反应」的 P0-D 乐趣缺口（部分兑现）。
- **记忆引擎注入式存储**：`MemoryEngine` 接收 `KVStore`，浏览器用 `memoryStore.ts`（localStorage），测试用 `MemStore`，互不污染。
- **红线闸门前置**：`OrderView` 在渲染前跑 `runForbiddenCheck`，red_light 命中即拦截，作为发布硬闸门。
