# docs/memory/ · 跨设备共享项目记忆

> **用途**：whoknow.me 项目"应跨设备共享的长期记忆"的**规范落点**。本目录纳入 git，多台电脑 `git pull` 即一致，无需任何 .gitignore 例外。
> **建立日期**：2026-07-26（多设备协作 memory 同步方案落地）

## 为什么需要它

memory 系统分三层（详见 `CONSTITUTION.md` 与工作室角色定义）：
- **L1 云端**：profile + 对话历史 → 自动跨设备（免维护，但不可精确编辑）
- **L2 用户级**：`~/.workbuddy/MEMORY.md`（home 目录）→ **不**跨设备
- **L3 项目级**：`.workbuddy/memory/`（项目内，被 `.gitignore` 忽略）→ **不**跨设备

本地 memory 文件（L2/L3）本就不是为"跨设备共享"设计的，是**本机工作台日志**（含机器路径、append-only 易并发冲突）。真正该跨设备记住的东西，应**落进仓库文档**——本目录即承担此职责。

## 分工

| 落点 | 跨设备？ | 内容 | 维护方式 |
|---|---|---|---|
| **`docs/memory/`（本目录）** | ✅ git 同步 | 项目定位、产品矩阵、铁律分层、工程约定、部署红线、同步策略等"必须一致"的知识 | 人工维护，随里程碑更新 |
| `.workbuddy/memory/MEMORY.md` | ⚠️ `git add -f` 强制跟踪镜像 | 本机自动累积的工作记忆摘要 | 本机工作台，已强制跟踪作镜像 |
| `.workbuddy/memory/2026-*.md` | ❌ 留本机 | 每日工作日志（含机器路径、临时上下文） | 不共享、不提交 |
| `~/.workbuddy/MEMORY.md` | ❌ 留本机 | 用户级全局偏好（跨项目） | 用云盘同步 `~/.workbuddy` 可跨设备 |

## 写入规范

1. 只放"跨设备必须一致"的内容（项目级事实、约定、决策）。**不放**机器特定路径、临时状态、个人吐槽。
2. 重大变更（里程碑 M1→M4、架构调整、铁律修订）及时同步到此目录。
3. 与 `CONSTITUTION.md` 分工：CONSTITUTION 管"铁律/约定"，本目录管"项目事实与历史决策摘要"。
4. 修改后提交并 push，其他设备 `git pull` 即同步。
