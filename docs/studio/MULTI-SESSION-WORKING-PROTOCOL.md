# 多会话并行协作工作协议（MULTI-SESSION WORKING PROTOCOL）

> **定位**：`whoknow.me` 仓库由多个 WorkBuddy 会话并行协作，且常共享同一工作目录 `D:\AI-Project\whoknow.me`、同时读写文件。本协议是「如何区分会话 / 如何隔离存储 / 如何写作」的**权威细则**。
> **关系**：`ROLES.md` §6.7 为本协议摘要；本协议为完整操作手册。两处冲突以本协议为准。
> **适用**：同机或跨机任意数量的会话同时运行、同时写作（未来常态）。

---

## 📌 新会话启动速做（读到本文件立刻做这 5 步）

1. **取会话 ID**：`echo "$CODEBUDDY_SESSION_ID"` —— 这是本会话唯一隔离键。
2. **建隔离目录**：`mkdir -p "memory/sessions/$CODEBUDDY_SESSION_ID"`，本会话日志只写 `memory/sessions/<SID>/YYYY-MM-DD.md`，**绝不裸写**共享 `memory/YYYY-MM-DD.md`。
3. **读权威地图**：`docs/studio/ROLES.md` §0（机器→角色映射）+ §6.7（本协议摘要）+ `WIP.md`（在制通报）。
4. **确认范围**：本会话范围以**用户 live 指令**为准；对照 `ROLES.md` §0 定 lane，不碰其他 App 文件（L1-T5 多 App 共存红线）。
5. **登记 WIP**：在 `WIP.md` 写一行 `[机器/角色] 任务 @ 文件`，结束划掉。

> 隔离键**只能**用 `CODEBUDDY_SESSION_ID`。Expert ID / 计算机名 / 分支名都不唯一，不能作隔离键（实证见 §1.4）。完整操作手册即本协议全文。

---

## 0. 适用范围与核心矛盾

- **场景**：N 个 WorkBuddy 会话指向同一工作目录，读写同一批文件（含 `.workbuddy/memory/`、`docs/studio/`、各 App 源码）。
- **核心矛盾**：会话各自按用户 live 指令拿到互斥范围（如「mart 专」与「brain 专」），但若都裸写同一共享文件，会互相看到对方条目、各自误判为「被污染」，进而覆盖或写花。
- **治本原则**：用**会话级唯一 ID** 隔离，而非靠人工协调「谁先写」。

---

## 1. 如何区分（身份锚点）

### 1.1 会话级唯一 ID（唯一权威隔离键）
- **`CODEBUDDY_SESSION_ID`**（环境变量，每会话唯一且稳定）是区分会话的**唯一**可靠标识。
- 每次写入 / 读取隔离文件前，先取该值：`echo "$CODEBUDDY_SESSION_ID"`。
- 该 ID 在会话生命周期内不变（实测多次读取一致），可作文件名 / 目录名 / 记忆锚点。

### 1.2 机器级 ID
- **`device-id`**（`~/.workbuddy/device-id`）区分物理机器（`701-PC` / `DuckyPC`）。
- 跨机场景须叠加 `device-id` + `CODEBUDDY_SESSION_ID`，避免不同机器生成相同 SID 短码时混淆。

### 1.3 角色与范围
- 角色由 `ROLES.md` §0 计算机名映射 + 用户 live 指令确定。
- **范围以用户在本会话的 live 指令为准**，不被共享日志中其他会话的条目覆盖。

### 1.4 不可作隔离键的反例
| 候选键 | 为何不行 | 实证 |
|---|---|---|
| Expert ID（如 `ex_qC4H6Q95jdkw`） | 多会话可选同一 Expert，非会话级唯一 | mart 与 brain 会话同选该 Expert 即证 |
| 计算机名（`701-PC` / `DuckyPC`） | 同机多会话共享同一计算机名 | 同机 mart/brain 会话同名 |
| git 分支名 | 多会话可同分支，且可切换 | `agent-mart` 可被多会话 checkout |
| 进程 PID | 不稳定，会话重启即变 | — |

### 1.5 会话自报（启动首句必做）
每个会话启动后立即执行并自报：
```bash
echo "SID=$CODEBUDDY_SESSION_ID"
echo "DEVICE=$(cat ~/.workbuddy/device-id)"
echo "BRANCH=$(git rev-parse --abbrev-ref HEAD)"
```
对照 `ROLES.md` §0 确认角色与范围后再动手。

## 2. 如何保存文件（存储隔离）

### 2.1 每日记忆日志（最高频冲突源）
- ✅ **写**：`memory/sessions/<CODEBUDDY_SESSION_ID>/YYYY-MM-DD.md`（执行写入方会话独家写）。
- ❌ **禁**：裸写共享 `memory/YYYY-MM-DD.md`。
- 共享 `YYYY-MM-DD.md` 仅作历史沉淀；若必须写，每条目标注 `[SID 短码 / scope]` 标签（如 `[f86c7b / brain]`）。
- 子目录天然支持任意数量会话，互不撞名。

### 2.2 长期记忆 `MEMORY.md`
- 仅承载标注 `verified` + 来源 session 的**跨会话事实**（如「brain 实测由 DuckyPC 主责」）。
- 改前先读全文件；新增条目须带 `来源 session=<SID>` + 验证状态。
- 不写本会话临时判断 / 推测（临时判断落本会话隔离文件）。

### 2.3 代码 / 文档产出（按 lane 落）
- 落 `ROLES.md` §0/§1 规定的本会话 lane 目录。
- 跨 lane 改动须先在对话知会负责会话并获同意（`ROLES.md` §2.1 红线）。

### 2.4 git 工作线隔离
- 每会话在**专属分支 / 工作线**开发（如 `agent-mart` / `agent-waimai`），以 PR / squash 合 `main`（受保护，禁直推）。
- 提交用精确 `git add <paths>`；**禁用 `git add -A` / `git add .`**（防误纳其他会话的未跟踪产物 —— 参见 2-A 教训：33 个 2-A brain 半成品曾被 `git add .` 风险覆盖）。

### 2.5 会话临时产物命名
- 临时草稿加 `<SID 短码>-` 前缀，或落 `memory/sessions/<SID>/` 子目录，避免与共享文件撞名。

### 2.6 跨会话共享产物传递
- 经 **git + 协作章程**（`ROLES.md` / `WIP.md` / `INDEX.md`）传递，不裸写对方隔离文件。

### 2.7 共享章程双闸门
- 修订协作章程（`ROLES.md` / `INDEX.md` / `WIP.md` / `MEMORY.md`）须：§0↔§1 范围一致 + 改前 `grep` 核查依赖 + 改后全文回扫对齐（防同文档两处结论相反，见 `REPO-STRUCTURE-CONVENTION.md` §7）。

## 3. 如何写作（写作纪律）

### 3.1 隔离文件头标注（必带）
每个会话隔离文件头部用 HTML 注释标注锚点：
```html
<!--
session: <CODEBUDDY_SESSION_ID>
device: <device-id> (机器名)
role: <职责描述>
started: <ISO8601 时间锚>
owner: <机器 / 角色 / 自称>
discipline: 本文件由执行写入方会话独占写，其他会话不应追加
-->
```

### 3.2 客观表述红线（宪法 L2-C9）
- **禁止集**：含第一、二人称及其复数、反身指代的读者相对代词，近指与远指处所及单机指代，以及含『自』字的反身自指构词。完整枚举与豁免（如「您」「自嘲」不在拦截集）见 `CONSTITUTION.md` L2-C9 细则。
- **不在拦截集**：`您`（NPC 台词可用）、`自嘲`。
- 时间敏感陈述须带日期锚；修订文档前按 L2-C9 全文回扫。
- 预提交钩子 `.githooks/pre-commit` 长期兜底（拦截协作约定文档新增的读者相对主观表述）。

### 3.3 范围以用户 live 指令为准
- 执行写入方会话的范围由用户 live 指令确定；共享日志中其他会话的范围判断**不视作本会话权威**。
- 若用户前后指令冲突，以**最新** live 指令为准，并在本会话隔离文件标注纠正历史误记。

### 3.4 读取前确认归属
- 读文件先判是「会话隔离」还是「共享」：
  - 会话隔离：`memory/sessions/<SID>/` 子目录 → 仅该 SID 会话权威。
  - 共享：`docs/studio/` / `MEMORY.md` / `YYYY-MM-DD.md` → 按 session 标签甄别，仅信 `verified`+来源段。

### 3.5 冲突处置
- 发现双向裸写污染：执行写入方会话立即改隔离方案（落 `memory/sessions/<SID>/`）+ 通知对端。
- 以**用户最新 live 指令 + ROLES.md** 为权威；互不覆盖对方隔离文件。
- 误记纠正：在隔离文件标注「X 段为误记（来源 SID=…），以本段为准」，不静默改写对方文件。

### 3.6 引用实体化
- 用机器名 / 角色名 / `CODEBUDDY_SESSION_ID` / 文件路径指代实体，不依赖上下文代词（避免「这个」「那个」「上面说的」）。

## 4. 协作红线（汇总）

1. **L1-T5 多 App 共存**：不碰其他 App 文件（`whoknow-waimai/` 归 DuckyPC 等）。
2. **不裸写他人 session 隔离文件**：`memory/sessions/<其他 SID>/` 只读不写。
3. **隔离键正确**：只用 `CODEBUDDY_SESSION_ID`；禁用 Expert ID / 计算机名 / 分支名作会话隔离键。
4. **共享文件改前协商**：`ROLES.md` §2.2 规则（意图说明 → 对方 ack / 人工拍板 → 改后告知）。
5. **提交精确**：`git add <paths>`，禁 `git add -A` / `git add .`。

---

## 5. 启动 / 交接清单

### 5.1 会话启动
1. `echo` 锚点（§1.5）。
2. 读 `ROLES.md` §0 / §6.7 + 本协议 + 本会话隔离记忆 + `WIP.md`。
3. 确认范围，在 `WIP.md` 登记。

### 5.2 开改前
- `WIP.md` 登记一行：`[机器 / 角色] 任务简述 @ 文件`，结束划掉。
- 另一会话开工前先扫 `WIP.md`，避免双会话改同一文件。

### 5.3 结束 / 切换
- 隔离记忆写交接摘要（范围 / 进度 / 阻塞 / 未决项）。
- 更新 `WIP.md`。
- 精确 commit 本 lane，不误纳他人产物。

---

## 6. 冲突检测与处置流程

- **改共享文件前**：`git status` / `git diff` 查是否有其他会话同文件在制（未提交改动）。
- **双向裸写污染**（实证：mart 会话与 brain 会话互写共享 `2026-09-01.md`）：
  1. 执行写入方会话停止裸写，改落 `memory/sessions/<SID>/`。
  2. 在隔离文件标注污染来源（SID + 反向段落内容）。
  3. 通知对端改用本协议 §2.1。
  4. 若共享文件已被污染，由污染段所属 SID 会话负责清理 / 回写带标签版本。
- **SID 子目录优势**：天然无锁、无命名冲突，支持任意数量会话并发写作。

---

## 7. 反模式（禁止清单）

- ❌ 裸写共享 `memory/YYYY-MM-DD.md`（最高危）。
- ❌ 用 Expert ID / 计算机名 / 分支名作会话隔离键。
- ❌ 把其他会话范围判断当本会话权威。
- ❌ 互相覆盖 / 静默改写对方隔离文件。
- ❌ `git add -A` / `git add .` 误纳他人未跟踪产物。
- ❌ 协作文档出现读者相对代词 / 模糊指代（L2-C9）。

---

## 8. 规模扩展（N 会话）

- **SID 子目录**天然支持任意数量会话并发，无上限、无命名冲突。
- **共享 `MEMORY.md`** 仅承载 `verified` 跨会话事实，降噪、防膨胀。
- **新会话接入**：§1.5 自报 → 读 ROLES §0/§6.7 + 本协议 → 建 `memory/sessions/<SID>/` → 登记 `WIP.md`。
- **第三台机器**：`ROLES.md` §0/§1 增列自身行 + 本机身份文件写入「先读 ROLES」（§5 第0步）。
