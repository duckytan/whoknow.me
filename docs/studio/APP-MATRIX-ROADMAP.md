## 0. 目的与边界

本文件为胡闹宇宙**产品矩阵的扩展构思**，回答一个问题：**在 waimai（外卖）+ mart（导购）两款已立项的基础上，还能长哪些 app？各自的玩法与理由是什么？**

- **性质**：构思草稿，**不是**已排期的执行计划。是否落地、何时落地，须经锡哥/錡哥拍板并进入对应里程碑。
- **约束前置**：本构思全程受 [`CONSTITUTION.md`](../../CONSTITUTION.md) 三层铁律 + 总纲 §2「金克木·克制扩张」约束——**v2 单产品跑通前，扩展一律冻结铺工，只埋空扩展点**。
- **红线不可妥协**：不制造焦虑、不人身攻击、不点名真实明星/物价/品牌（黄灯须化名）；外壳真实、荒诞仅限对话+虚构。
- **当前规模**：已归档 **16 款候选**（原 6 + 新增 10），归为 **8 大类**（见 §3），全按 §1 母题过筛。
- **🔒 解锁门禁（金克木硬约束 · 三司会审 2026-07-28 裁定）**：本文件 16 款均为**灵感候选 backlog**，**任一款进入 Phase 1 GDD 正式开发的前提 = ① waimai 真机 playtest 硬闸门 PASS（总纲行动项 C 仍 OPEN）② mart v1 跑通验证**。门禁未过前，本文件仅作方向性参考，**禁止任何 app 进入排期 / 动工**。

## 1. 品类母题（筛选器）

一个合格胡闹 app 必须**同时满足**以下 7 条，否则宁可不碰：

| # | 条件 | 说明 |
|---|---|---|
| 1 | **真实外壳** | 披一个全民熟悉的生活/消费类 app 外衣，用户零学习成本（零摩擦铁律） |
| 2 | **荒诞内核只藏两处** | 仅对话台词 + "本次为虚构"；界面/流程/手感必须真（真实外壳·荒诞内核边界） |
| 3 | **截图即胜利** | 必须存在一个"用户会截图发朋友圈"的瞬间（三铁律之一） |
| 4 | **零负担** | 无 gacha、无断签损失厌恶、无焦虑 push |
| 5 | **可复用 brain 契约** | NPC 台词池 / 记忆分级 / 禁忌词闸门能直接套用，brain 作"胡闹人格中枢"多租户供给 |
| 6 | **1 人无后端可行** | 纯前端 + localStorage + 静态话术池，不依赖实时服务 |
| 7 | **红线安全** | 不制造焦虑、不人身攻击、不点名真实明星/物价/品牌 |

**范本**：waimai = 披外卖 + DRAMA 记忆引擎；mart = 披导购 + 选招制博弈。以下 16 款皆按此模子生长。

### 2.1 胡闹打车（whoknow-ride）· 披出行 app 外衣的虚拟打车

- **外壳**：真实打车流程——输入目的地 → 叫车 → 候车 → 行程 → 到达 → 评价。
- **玩法**：每次叫车 = 抽一个"司机 persona"（社恐 / 话痨 / 哲学 / 暴躁 / 唱见）；行程中可"选话题"触发司机不同反应（复刻 waimai 的 DRAMA 四阶段 + mart 选招制）；到达后司机甩一句"人生总结"或奇葩小费梗。
- **截图爆点**：司机疯狂金句示例（对乘客目的地偏差的吐槽，如"这目的地闭着眼都能开错"）+ 魔性评价页。
- **理由**：打车是车上无聊刷手机的高频场景，天然命中"想笑 + 管不住手"痛点滤网；司机 persona 比老板更天然戏精；**DRAMA-ENGINE + brain 信封直接复用**（把 `boss` 换 `driver`）。
- **复用度**：★★★★★（最高）
- **红线**：不碰真实路况事故；虚拟城市名泛化。

### 2.2 胡闹占卜（whoknow-fate）· 披星座/抽签外衣的离谱占卜

- **外壳**：真实占卜 app——选星座 / 摇签 / 塔罗。
- **玩法**：每日一卦（**零负担**：不强迫每天来、不 push）；卦象 + 一句胡闹解读 + "今日宜忌"清单；"摇一摇"重抽，每次随机荒诞。
- **截图爆点**：离谱卦象（"今日财运：在沙发缝里发现三块五"）+ 宜忌梗（宜摸鱼 / 忌开会）。
- **理由**：占卜是**截图传播力最强**品类（朋友圈晒卦祖传习惯）；纯前端随机 + 话术池、零后端；完美契合 *Who knows?* 调性。
- **复用度**：★★★★☆（话术池模式复用，但无记忆引擎需求）
- **红线**：**绝不能制造焦虑**——不出"血光之灾 / 破财"式预言，只出躺平宜忌；明确"纯属胡闹"免责声明。

### 2.3 胡闹云养宠（whoknow-pet）· 披养宠 app 外衣的毒舌电子宠物

- **外壳**：真实养宠 app——喂食 / 撸 / 状态。
- **玩法**：宠物是哲学家 / 毒舌猫狗，记忆分级（被善待 → 傲娇，被冷落 → 阴阳怪气）；每日撸宠选互动 → 宠物反应；图鉴 = 收集宠物语录。
- **截图爆点**：宠物金句卡（直接复用 waimai 手写体 + 品牌绿截图样式）。
- **理由**：宠物内容天生传播；单机零负担；记忆引擎 `UserStats` 模式直接搬 waimai。几乎不踩红线。
- **复用度**：★★★★★（记忆引擎直接复用）
- **红线**：无特殊，安全区。

### 2.4 胡闹天气（whoknow-weather）· 披天气 app 外衣的魔性播报

- **外壳**：真实天气 app——城市 / 温度 / 预报。
- **玩法**：看天气 = 收一段魔性播报 + 宜忌；可切换"城市 persona"（每个虚拟城市一个播报风格）。
- **截图爆点**：魔性天气文案（"28°，体感像被生活扇了一巴掌"）。
- **理由**：天气超高频打开；但"实用天气"对 1 人无后端没意义——做成"胡闹天气梗图生成器"反而传播强。
- **复用度**：★★★☆☆（话术池 + persona，无记忆引擎）
- **注意**：真实温度需外部 API（违背无后端）；建议**纯虚拟城市 weather**，更稳更胡闹。

### 2.5 胡闹打工（whoknow-work）· 披办公/招聘 app 外衣的虚拟职场

- **外壳**：真实打卡 / 任务 app。
- **玩法**："上班" = 处理荒诞任务（帮老板点奶茶 / 写周报生成器）；选不同应对触发同事不同反应（选招制博弈）；成就 = 摸鱼大师 / 周报鬼才。
- **截图爆点**：老板抢麦语录 / 同事离谱需求。
- **理由**：打工人共鸣极强，截图传播天然；选招制直接复用 mart。
- **复用度**：★★★★☆（选招制 + 博弈复用）
- **红线**：**需虚拟化公司**；不点名真实企业 / 品牌 / 老板人身——比前几款更"野"，设计要更克制。

### 2.6 胡闹相亲（whoknow-love）· 披交友 app 外衣的虚拟社交

- **外壳**：真实交友 app——滑卡 / 资料卡。
- **玩法**：滑卡 → 聊天 → 对方奇葩反应 → "成了 / 黄了"结局收集；资料卡离谱（"爱好：和洗衣机吵架"）。
- **截图爆点**：相亲对象奇葩语录。
- **理由**：社交共鸣 + 截图传播双高。
- **复用度**：★★★☆☆（滑卡 + 结局收集，轻记忆）
- **红线**：**最敏感**——不人身攻击、不物化、不拟真引向真实交友风险；建议走"纯虚构喜剧"，放最远期。

### 2.7 胡闹家政（whoknow-home）· 披上门维修/保洁外衣的毒舌师傅

- **外壳**：真实家政预约——选服务（通下水道 / 修空调 / 大扫除）→ 师傅接单 → 进度条。
- **玩法**：荒诞藏在**维修师傅的实时语音气泡**（DRAMA-ENGINE 四阶段：到场→吐槽房屋 Layout→边修边聊人生→离场甩金句）；本次"消费"为虚构订单。
- **截图爆点**：进度 80% 时气泡弹出示例台词——"住户水管修好，但生活漏洞建议走心理咨询"。
- **理由**：家家都有维修糟心事，真实预约界面 + 毒舌师傅 = 极强反差；"谁家没个不靠谱师傅"共鸣满点，易转发。
- **复用度**：★★★（persona 池 + DRAMA-ENGINE + 记忆分级）
- **红线**：不点名真实品牌家电；故障描述纯虚构，不教真维修（避免被当教程误用）。

### 2.8 胡闹导航（whoknow-nav）· 披地图导航外衣的吐槽导航员

- **外壳**：真实导航 app——输入目的地 → 真实路线规划 → 导航播报。
- **玩法**：**路线数据必须真**（否则误导出行）；荒诞只藏**导航员的吐槽旁白**（话术池抽取），如"前方 500 米右转，和您的人生一样突然"。
- **截图爆点**：导航 HUD 角落小气泡——"本次行程预计 23 分钟，比您上一段感情短"。
- **理由**：导航是零学习成本全民工具；**真实路线反衬荒诞旁白**正是 Who knows? 精髓；开车/乘车时最易顺手截图。
- **复用度**：★★（persona 池 navigator + 话术池；记忆轻量 commute_freq）
- **红线**：**路线必须真实**，绝不虚构转向/限速，避免被当真导航引发危险；吐槽仅限于语气，不篡改地理事实。

### 2.9 胡闹美发（whoknow-salon）· 披美发预约外衣的浮夸 tony

- **外壳**：真实美发预约——选门店/项目 → tony 接单 → 服务进度。
- **玩法**：荒诞藏在 **tony 的洗脑推销气泡 + 选招制博弈**（"办卡吗？"给玩家三选项，每个选项触发不同戏精回应）。
- **截图爆点**：tony 气泡——"您这发际线，建议直接植个草坪，办卡打八折"。
- **理由**：tony 话术是全网 meme，真实预约壳 + 浮夸人设天然好笑；"被推销"是全民共同创伤。
- **复用度**：★★★（persona 池 + 选招制博弈 + 记忆分级办卡抗性）
- **红线**：不绑定真实连锁品牌；"植草坪"明显荒诞，不暗示真实医疗行为。

### 2.10 胡闹按摩（whoknow-spa）· 披上门养生外衣的毒舌按摩师

- **外壳**：真实养生预约——选项目（肩颈 / 全身）→ 师傅上门 → 服务中。
- **玩法**：荒诞藏在**按摩师傅边按边毒舌点评顾客体态人生**（话术池 + 轻 DRAMA-ENGINE）。
- **截图爆点**：师傅气泡——"您这肩颈，像极了您的工作态度：又硬又扛"。
- **理由**：打工人颈椎痛点 + 养生潮流；把"被按摩"变成"被透视人生"，反差舒适。
- **复用度**：★★（persona 池 + 话术池；记忆轻量常按部位）
- **红线**：**纯养生闲聊，绝不做诊断/治疗声称**；不出现"治颈椎病"等医疗表述，规避医疗红线。

### 2.11 胡闹记账（whoknow-ledger）· 披记账工具外衣的毒舌账本 AI

- **外壳**：真实记账 app——记一笔 → 分类 → 月度报表。
- **玩法**：荒诞藏在**毒舌记账 AI 的月报评语**（"您本月奶茶支出 = 0.4 头牛"）；本次消费为虚构演示账目。
- **截图爆点**：月报卡片——"您在[虚构]上花了 X，够买半头黄牛，牛已为您铭记"。
- **理由**：人人有消费愧疚；把"心疼钱包"变成"被 AI 公开处刑"，传播欲强。
- **复用度**：★★★（记忆分级强 + 禁忌词闸门禁真实理财建议 + 话术池）
- **红线**：**极度虚拟化**——不接真实账户、不给投资建议、不推真实理财产品；明确"纯虚构娱乐账本"。

### 2.12 胡闹搬家（whoknow-move）· 披搬家货运外衣的扎心师傅

- **外壳**：真实搬家预约——填起终点 → 选车型 → 师傅接单 → 搬运进度。
- **玩法**：荒诞藏在**搬家师傅边搬边吐槽用户囤的没用东西**（DRAMA-ENGINE 四阶段 + 记忆分级读取"历史搬家频率"）。
- **截图爆点**：师傅气泡——"这箱比您存款还沉，里面是去年的购物车吗"。
- **理由**：搬家是全民痛苦记忆；"断舍离"话题自带传播；真实报价壳 + 扎心吐槽极好笑。
- **复用度**：★★★（persona 池 + DRAMA-ENGINE + 记忆分级搬家次数）
- **红线**：报价为虚构；不点名真实搬家公司；吐槽仅限物品，不人身攻击。

### 2.13 胡闹租房（whoknow-rent）· 披租房平台外衣的浮夸中介

- **外壳**：真实租房 app——筛选条件 → 房源列表 → 详情页。
- **玩法**：荒诞藏在**中介的浮夸房源描述**（选招制：玩家"砍价/质疑"触发不同戏精话术）；房源与交易均为虚构。
- **截图爆点**：房源卡片——"采光极佳，因为南墙塌了；地铁 200 米，按直线算"。
- **理由**：租房中介段子是全民梗；真实列表 UI 反衬离谱描述，截图即笑点。
- **复用度**：★★★（persona 池 realtor + 选招制博弈 + 记忆分级预算/看房耐性）
- **红线**：**房源全虚构**，详情页加"本平台房源均为虚构喜剧内容"水印；不影射真实小区名引发误导。

### 2.14 胡闹快递（whoknow-express）· 披物流查询外衣的拟人包裹

- **外壳**：真实快递查询——输单号 → 物流时间轴。
- **玩法**：荒诞藏在**包裹拟人化自述**（话术池：包裹在分拣中心"思考了三天人生"），纯文本戏精。
- **截图爆点**：物流节点示例——"【已揽收】包裹离开商家，奔向未知收件人"。
- **理由**：人人查快递；把冷冰冰物流变成"会写诗的包裹"，治愈又戏精，转发无负担。
- **复用度**：★★（persona 池 package_ghost + 话术池；记忆轻量）
- **红线**：物流节点时间戳为演示数据，标注"虚构轨迹"；不绑定真实快递品牌单号规则。

### 2.15 胡闹酒吧（whoknow-bar）· 披调酒点单外衣的虚构调酒师

- **外壳**：真实调酒/点单（**虚拟，不真喝**）——选心情/基酒 → 调酒师出单 → 酒单卡片。
- **玩法**：荒诞藏在**调酒师按顾客"心情"调一杯虚构鸡尾酒 + 选招制互动**（"加冰吗？"触发戏精）；本次消费为虚构。
- **截图爆点**：酒单卡片——"【周一崩溃】柠檬 + 眼泪 + 一点希望，酒精 0%，致郁 100%，请勿酒驾（饮品为虚构不可饮用）"。
- **理由**：夜生活/emo 情绪是传播富矿；"调一杯专属鸡尾酒"有仪式感与分享欲。
- **复用度**：★★★（persona 池 bartender + 选招制 + 记忆分级心情标签）
- **红线**：**明确虚构、不真饮酒**；酒驾梗以虚构消解（"不可饮用"）；不鼓励真实过量饮酒。

### 2.16 胡闹相机（whoknow-cam）· 披美颜相机外衣的毒舌修图师

- **外壳**：真实美颜相机——拍照 → 美颜滑块 → 成片。
- **玩法**：荒诞藏在**毒舌 AI 修图师的实时点评气泡**（"已为您美颜，原图已就地销毁，勿念"）。
- **截图爆点**：修图界面气泡——"您这原图，建议直接当抽象艺术参展"。
- **理由**：自拍/修图是全民日常；"被 AI 当面嫌弃"自嘲向，极易截图自黑传播。
- **复用度**：★★（persona 池 beautician_ai + 话术池；记忆轻量美颜强度偏好）
- **红线**：点评仅针对**用户本人授权照片**的自嘲语境，不攻击/比对真实他人，规避人身攻击红线。

## 3. 聚类地图（8 大类 · 成簇解锁）

把 16 款按"生活域"归为 8 大类，便于**按类批量解锁**——同簇共享 persona 池与 tone，边际成本最低：

| 大类 | 成员 App | 解锁逻辑 |
|---|---|---|
| **A. 出行 Mobility** | ride(打车 2.1)、nav(导航 2.8) | 移动场景，共享"司机/导航员"persona 池 |
| **B. 到家服务 Home Errands** | waimai(外卖·在研)、home(家政 2.7)、move(搬家 2.12)、express(快递 2.14) | 上门/到手服务，共享"服务者毒舌"tone |
| **C. 变美与健康 Glow & Wellness** | salon(美发 2.9)、spa(按摩 2.10)、cam(美颜相机 2.16) | 形象经营域，共享"点评顾客"话术母题 |
| **D. 居住 Dwelling** | rent(租房 2.13) | 单一但高频痛点，待扩"装修/物业"补位 |
| **E. 消费与钱包 Commerce** | mart(商城·在研)、ledger(记账 2.11) | 花钱域，共享"消费虚构 + 吐槽"机制 |
| **F. 社交与陪伴 Social** | love(相亲 2.6)、bar(酒吧 2.15)、pet(云养宠 2.3) | 关系域，共享"虚构互动 + 情感投射" |
| **G. 职场 Hustle** | work(打工 2.5) | 单一，待扩"面试/开会"补位 |
| **H. 玄学日常 Omen Daily** | fate(占卜 2.2)、weather(天气 2.4) | 宜忌/运势域，共享"离谱卦象"母题 |

**批量解锁建议**：优先成簇上线——如先 B 类"到家三件套"共享一套 `service_worker` persona，边际成本最低；C/D/E 可组"形象经营"包；F 组做"关系喜剧"包。**明显空缺待补（第三波候选）**：内容创作类（Vlog/日记）、学习教育类（背单词/网课，需去焦虑化）、医疗虚拟化类（养生问诊，极重度虚拟化）——均符合 §1 筛选器。

## 5. 关键基建建议：brain 多租户化（多维信封）

趁现在把 `whoknow-brain` 的 envelope 契约从**单租户（waimai）**扩成**多租户**，这是总纲要的"空扩展点"：

- `meta` 增加 `app` 字段（取值如 `waimai` / `ride` / `fate` / `pet` …），标识内容归属。
- NPC 台词池按 `app` 隔离，但**共用**禁忌词闸门（`forbidden_check`）+ 记忆引擎（`UserStats` / `memoryTier`）。
- 将来每加一款 app = 往 brain 多塞一类 persona + 在 `meta.app` 注册，**不动架构**。

### 5.1 二次扩展新增：信封多维升级

基于 §2 的 16 款 + §3 的 8 大类，`design-strategist` 反推：仅 `app` 字段还不够——每款仍要手写 persona，未真正达成"加一款 app = 多塞一类 persona"。建议 `meta` 增加以下维度，让 brain 从"按 app 存"升级为"按 **(品类 × 角色 × 语气)** 路由"：

| 新增维度 | 取值示例 | 价值 |
|---|---|---|
| `category` | `home_errands` / `mobility` | **跨 app 复用 persona 池**——B 类 waimai 骑手 / home 维修 / move 搬家共享 `service_worker` 底层 persona，仅 tone 微调 |
| `persona_type` | `rider` / `repairman` / `bartender` / `package_ghost` | **brain persona 池主键**，定义一次即可被多 app 引用 |
| `tone` | `毒舌` / `佛系` / `戏精` / `治愈` | **同一 persona_type 跨 app 换 tone**（如 repairman 在 home 用毒舌、在 express 用治愈） |
| `memory_scope` | `["consumption_habit","frequency"]` | 声明本 app 对 `UserStats` 的读写维度，便于**跨 app 聚合画像**（如"该用户在 B 类所有 app 都是高频过度消费者"→ 通用吐槽素材） |
| `fiction_flag` | `booking_none` / `order_fiction` | **设计宪法的机器可校验闸门**——brain 据此硬拒任何"真下单/真支付"语义，从契约层守住红线② |

**示范信封**：
```json
{
  "app": "whoknow-nav",
  "meta": {
    "category": "mobility",
    "persona_type": "navigator",
    "tone": "毒舌",
    "engine": "phrase-pool",
    "memory_scope": ["commute_freq"],
    "fiction_flag": "booking_none"
  }
}
```

**落地收益**：新增一款 app 时，策划只需在 brain 注册 `persona_type`（或复用已有）+ 选 `category`/`tone`/`fiction_flag`，persona 与记忆分级自动继承，**真正达成"加一款 app = 往 brain 多塞一类 persona"**；且 `category`/`tone` 让跨 app 联动吐槽（如导航员说"您这路线规划，和您在记账 app 里的预算一样离谱"）成为可能——把单点笑点升级为**宇宙级互文**。

> 此项属 P0-C 同类基建（归 `701-PC` / Agent-商城执行，DuckyPC 不跨做），须在 v2 跑通后随 M3 自动化一并推进，当前仅作设计预留。

## 6. 已知风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 一次性铺太多 app | 违背金克木，单产品未跑通即分散火力 | 严格按 §4 分档，M2 只验证"第二款"；§3 聚类确保成簇复用而非各自造轮 |
| 占卜/相亲踩焦虑或人身红线 | 红线 0 容忍，整包丢弃 | 占卜限定躺平宜忌 + 免责；相亲走纯虚构喜剧；均过 `forbidden_check` |
| 天气/菜谱需外部数据 | 违背无后端原则 | 改用纯虚拟城市 / 虚构菜谱，brain 供给 |
| 导航/家政踩真实安全红线 | 误导出行 / 被当真教程 | nav 路线必须真、吐槽仅语气；home 故障纯虚构不教维修 |
| 按摩/记账/酒吧踩医疗·金融·饮酒红线 | 红线 0 容忍 | spa 不做诊断声称；ledger 不接真账户/不给投资建议；bar 明确虚构不真饮 |
| brain 多租户改造影响 waimai 现有契约 | 字段二义、回归 | 沿用 ADR-001 数据形状权威；`meta` 维度为纯增量字段，向后兼容；`fiction_flag` 作硬闸门 |
| 跨 app 联动吐槽复杂度 | 宇宙级互文设计失控 | 仅 `category`/`tone` 同簇内联动，先做 M2 单 app 验证，互文留待成熟期 |
